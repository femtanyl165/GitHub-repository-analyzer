# RepoScope

**Настольное приложение для анализа GitHub-репозиториев и оценки состояния проекта.**

RepoScope собирает данные об активности, сообществе, документации и инженерных практиках репозитория. Результаты отображаются в тёмном интерфейсе с карточками показателей, разделами анализа и оценкой **Health Score от 0 до 100**.

Приложение написано на **Python и PySide6**. Доступны переносимые версии для **Windows** и **Ubuntu**.

## Возможности

- Анализ по имени `owner/repo` или ссылке на GitHub-репозиторий.
- Выбор репозитория по ссылке на список репозиториев пользователя.
- Просмотр описания, звёзд, форков, языков и даты последнего коммита.
- Показ активности за 30, 90 и 365 дней.
- Просмотр участников, открытых issues, pull requests и релизов.
- Оценка среднего времени закрытия issues и слияния pull requests по загруженным данным.
- Проверка наличия тестов, документации, лицензии и community-файлов.
- Проверка GitHub Actions, основной ветки, её защиты и последнего успешного workflow.
- Просмотр зависимостей и данных Dependabot, если GitHub предоставляет к ним доступ.
- Отображение README с заголовками, таблицами, ссылками и блоками кода.
- Настраиваемая оценка: включение критериев, изменение порогов и весов.
- Фоновая загрузка с отображением этапов, отменой анализа и подгрузкой списков.
- Обработка ошибок сети, неверного токена, ограничений GitHub API и недоступных репозиториев.

## Готовые версии

Для запуска готовых сборок устанавливать Python и библиотеки Python отдельно не требуется. Для анализа репозиториев нужен интернет.

| Система | Сборка | Файл запуска |
| --- | --- | --- |
| Windows 10/11, Intel/AMD, x64 | `RepoScope-Windows-x64.zip` | `RepoScope.exe` |
| Ubuntu 26.04, Intel/AMD, x86_64 | `RepoScope-Ubuntu-26.04-x86_64.tar.gz` | `RepoScope` |

### Windows

1. Распакуйте ZIP-архив через **«Извлечь всё»**.
2. Откройте папку `RepoScope-Windows-x64`.
3. Запустите **`RepoScope.exe`** двойным щелчком.

Сохраняйте папки `_internal` и `source` рядом с EXE: они нужны приложению. Запускайте программу из распакованной папки.

### Ubuntu

1. Распакуйте архив.
2. Откройте папку `RepoScope-Ubuntu-26.04`.
3. Запустите **`RepoScope`** двойным щелчком.

Если выполнение запрещено, разрешите запуск файла как программы в его свойствах. Можно также открыть терминал в распакованной папке и выполнить:

```bash
chmod +x RepoScope
./RepoScope
```

Если у вас отдельный файл `RepoScope-Ubuntu-26.04-x86_64`, используйте его имя:

```bash
chmod +x RepoScope-Ubuntu-26.04-x86_64
./RepoScope-Ubuntu-26.04-x86_64
```

Ubuntu-сборка рассчитана на графическую среду Ubuntu Desktop.

## Как пользоваться

1. Введите имя или ссылку на репозиторий, например:

   ```text
   octocat/Hello-World
   https://github.com/octocat/Hello-World
   ```

2. При необходимости выберите профиль оценки через **«Критерии»**.
3. Нажмите кнопку анализа и дождитесь завершения загрузки.
4. Изучите результат в разделах приложения.

| Раздел | Содержимое |
| --- | --- |
| Обзор | Основные показатели, описание, языки и оценка проекта |
| Активность | Коммиты, issues и pull requests |
| Сообщество | Участники и релизы |
| Качество проекта | Инженерные практики, зависимости и сведения о безопасности |
| README | Документация репозитория |

Чтобы выбрать репозиторий из профиля пользователя, можно вставить ссылку вида:

```text
https://github.com/octocat?tab=repositories
```

Длинные списки подгружаются кнопками **«Показать ещё»**. Во время загрузки анализ можно отменить.

## Оценка проекта

**Health Score** рассчитывается по выбранному профилю и его требованиям. По умолчанию используется профиль **Open Source**.

| Профиль | Основной акцент |
| --- | --- |
| Open Source | Сообщество, документация, активность и базовые инженерные практики |
| Рабочий проект | Тесты, автоматизация, защита изменений и обработка PR |
| Учебный проект | Понятность, документация, завершённость и базовые практики разработки |

В библиотеке доступны **12 критериев**: свежесть проекта, активность за 90 дней, README, тесты, GitHub Actions, лицензия, защита основной ветки, скорость обработки PR, известные уязвимости, участники, релизы и документация.

Нажмите **«Критерии»** до анализа или **«Настроить»** в карточке результата, чтобы включить нужные критерии и изменить их веса и пороги. Веса нормализуются автоматически. После применения настроек уже загруженный результат пересчитывается без повторного запроса к GitHub.

Нажатие на карточку оценки открывает вклад каждого критерия, пояснения и рекомендации. Критерии, для которых GitHub не предоставил достаточно данных, исключаются из расчёта итоговой оценки.

## Токен GitHub

Публичные репозитории можно анализировать без токена. Токен позволяет использовать возможности GitHub API с доступными вашей учётной записи разрешениями и увеличить лимит запросов.

Для готовой сборки создайте рядом с файлом запуска текстовый файл **`.env`**:

```dotenv
GITHUB_TOKEN=ваш_токен
```

В Windows-архиве есть `.env.example`: скопируйте его, переименуйте копию в `.env` и впишите токен.

Готовые сборки также поддерживают:

- **Windows:** `%APPDATA%\RepoScope\.env`.
- **Ubuntu:** `~/.config/reposcope/.env` или каталог `reposcope` внутри `XDG_CONFIG_HOME`, если эта переменная задана.
- **Обе системы:** переменную окружения `GITHUB_TOKEN`.

После изменения токена перезапустите приложение. Не публикуйте `.env` вместе с исходниками. Личный токен разработчика в готовые архивы не включён.

Некоторые сведения, включая защиту ветки и alerts Dependabot, могут требовать дополнительных разрешений. Если доступа нет, приложение отмечает соответствующие данные как недоступные и сохраняет остальные результаты.

## Запуск исходного проекта

Для исходной папки проекта с `main.py` и `requirements.txt` требуется **Python 3.10 или новее**.

### Windows

Откройте командную строку в папке проекта:

```bat
python -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
python main.py
```

### Ubuntu

Откройте терминал в папке проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

В Ubuntu для создания виртуального окружения должен быть доступен пакет `python3-venv`.

Эти команды относятся к исходному проекту. В готовых архивах используются отдельные точки входа: `main_windows.py` и `main_linux.py`.

## Проверка

В исходном проекте, после установки зависимостей:

```bash
python -m pytest
```

Для визуальной проверки интерфейса без запросов к GitHub:

```bash
python tools/preview_ui.py
```

Снимки сохраняются в `outputs/design-preview/`.

Ubuntu-сборка проверена на Ubuntu 26.04.1 x86_64. Запуск Windows EXE, открытие разделов, диалогов и закрытие окна проверены через Wine 10; проверка на физическом компьютере с Windows здесь не проводилась.

## Возможные проблемы

| Проблема | Что сделать |
| --- | --- |
| Windows EXE не запускается после переноса | Распакуйте архив полностью и сохраните папки `_internal` и `source` рядом с EXE |
| В Ubuntu запрещено выполнение | Разрешите запуск в свойствах файла или используйте `chmod +x` |
| Превышен лимит GitHub API | Дождитесь времени обновления лимита, указанного приложением, либо настройте токен |
| Токен не принят | Проверьте значение `GITHUB_TOKEN` и перезапустите приложение |
| Репозиторий недоступен | Проверьте адрес и наличие доступа к репозиторию |
| Данные о безопасности не показаны | Проверьте доступность функции в репозитории и разрешения токена |
| README не найден | В выбранном репозитории может отсутствовать README |

При ошибке запуска Windows-версии диагностический журнал сохраняется в `%LOCALAPPDATA%\RepoScope\startup-error.log`.

## Как интерпретировать результаты

RepoScope оценивает признаки состояния репозитория по данным GitHub. Проверки наличия тестов и документации основаны на структуре файлов; само приложение не выполняет тесты анализируемого проекта. Часть показателей зависит от загруженных страниц, доступности статистики и разрешений GitHub.

Оценка помогает сравнивать проекты по выбранным требованиям, но сама по себе не подтверждает корректность кода или отсутствие уязвимостей.
